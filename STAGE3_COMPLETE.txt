═══════════════════════════════════════════════════════════════════
  АРХИТЕКТУРА GDT
═══════════════════════════════════════════════════════════════════

Global Descriptor Table (GDT):
───────────────────────────────

┌─────────────────────────────────────────────────────────────┐
│ Индекс │ Селектор │ Тип  │ Ring │ Описание                 │
├─────────────────────────────────────────────────────────────┤
│   0    │   0x00   │ NULL │  -   │ Нулевой дескриптор       │
│   1    │   0x08   │ Code │  0   │ Код ядра                │
│   2    │   0x10   │ Data │  0   │ Данные ядра              │
│   3    │   0x18   │ Code │  3   │ Код пользователя         │
│   4    │   0x20   │ Data │  3   │ Данные пользователя      │
└─────────────────────────────────────────────────────────────┘

Параметры всех сегментов:
  База:          0x00000000 (начало памяти)
  Лимит:         0xFFFFFFFF (4GB)
  Гранулярность: 4KB (лимит × 4096)
  Размер:        32-bit

Модель памяти: Flat Memory Model
  → Вся память доступна как единое адресное пространство
  → Сегментация используется только для защиты (Ring 0/3)

═══════════════════════════════════════════════════════════════════
  СТРУКТУРА ДЕСКРИПТОРА (8 байт)
═══════════════════════════════════════════════════════════════════

 63    56 55  52 51  48 47    40 39    32 31    16 15     0
┌────────┬──────┬──────┬────────┬────────┬────────┬────────┐
│ Base   │Flags │Limit │ Access │ Base   │ Base   │ Limit  │
│[31:24] │      │[19:16]│  Byte  │[23:16] │[15:0]  │[15:0]  │
└────────┴──────┴──────┴────────┴────────┴────────┴────────┘

Access Byte (биты 47-40):
  Бит 7:   Present (P)         - 1 = в памяти
  Бит 6-5: Privilege (DPL)     - 00=Ring0, 11=Ring3
  Бит 4:   Descriptor Type (S) - 1 = код/данные
  Бит 3:   Executable (E)      - 1 = код, 0 = данные
  Бит 2:   Direction/Conforming
  Бит 1:   Readable/Writable   - 1 = чтение/запись
  Бит 0:   Accessed (A)        - устанавливается CPU

Flags (биты 55-52):
  Бит 7: Granularity (G)       - 1 = 4KB страницы
  Бит 6: Size (D/B)            - 1 = 32-bit
  Бит 5: Long Mode (L)         - 0 (не используется)
  Бит 4: Reserved              - 0

═══════════════════════════════════════════════════════════════════
  ПРОЦЕСС ЗАГРУЗКИ GDT
═══════════════════════════════════════════════════════════════════

1. kernel_main() вызывает gdt_init()
   ↓
2. gdt_init() создаёт таблицу дескрипторов в памяти
   • Заполняет gdt_entries[5]
   • Настраивает gdt_ptr (limit + base)
   ↓
3. gdt_init() вызывает gdt_flush()
   ↓
4. gdt_flush.asm (ассемблер):
   • LGDT [gdt_ptr]              - загрузка в GDTR
   • MOV DS/ES/FS/GS/SS, 0x10   - обновление сегментов данных
   • JMP 0x08:.flush             - far jump для обновления CS
   ↓
5. Процессор использует новую GDT
   • CS = 0x08 (код ядра)
   • DS/ES/FS/GS/SS = 0x10 (данные ядра)

═══════════════════════════════════════════════════════════════════
  ФУНКЦИИ РАБОТЫ С ПОРТАМИ I/O
═══════════════════════════════════════════════════════════════════

Порты ввода-вывода (0x0000 - 0xFFFF) используются для
взаимодействия с аппаратными устройствами.

Функции (inline ассемблер):
  uint8_t  inb(uint16_t port)   - чтение байта
  void     outb(port, data)     - запись байта
  uint16_t inw(uint16_t port)   - чтение слова
  void     outw(port, data)     - запись слова
  uint32_t inl(uint16_t port)   - чтение dword
  void     outl(port, data)     - запись dword
  void     io_wait(void)        - задержка I/O

Примеры портов:
  0x20, 0x21 - PIC (Programmable Interrupt Controller)
  0x40-0x43  - PIT (Programmable Interval Timer)
  0x60, 0x64 - Клавиатура PS/2
  0x3D4-0x3D5 - VGA CRTC

           Запусти с отладкой: qemu-system-i386 -d int,cpu_reset

❌ Проблема: "undefined reference to gdt_flush"
✓ Решение: Проверь что gdt_flush.asm в Makefile (ASM_SOURCES)
           Пересобери: make clean && make

❌ Проблема: Чёрный экран после загрузки GDT
✓ Решение: Проверь дескрипторы (база=0, лимит=0xFFFFFFFF)
           Проверь Present bit в access byte

✓ Решение: Используй GCC 4.8+, проверь флаги -ffreestanding
