# Этап F — типографика, единый лаунчер, движение, жизненный цикл окон

Статус: **код готов и компилируется**, визуальная проверка в QEMU — за вами
(в песочнице, где готовился этап, нет `nasm`, `grub-mkrescue`, `xorriso`,
`qemu-system-x86_64`, поэтому ISO не собирался и скриншоты не снимались).

Всё ниже относится только к x86_64-ветке (`kernel/arch/x86_64`, `kernel/kernel64_main.c`).
Легаси i386 (`kernel/kernel.c`, `kernel/gui/*`) намеренно не трогался.

---

## 1. Гладкая типографика вместо битмапа 8×16

Было: единственный шрифт `font8x16.c` — моноширинный битмап, 8 px на символ,
без кернинга, без насыщенностей, без размеров. Любая «Pearl»-вёрстка с ним
выглядит как терминал.

Стало: собственный движок `ui_font` с офлайн-генерацией атласа из TTF.

| Что | Где |
|---|---|
| Генератор атласа (host, Pillow) | `tools/gen_ui_font.py` |
| API движка | `kernel/arch/x86_64/ui_font.h` |
| Рендер | `kernel/arch/x86_64/ui_font.c` |
| Сгенерированные данные (594 646 Б) | `kernel/arch/x86_64/ui_font_data.c` |

Возможности:

* 8 начертаний: пропорциональные 12 / 14 / 16 / 20 / 28 / 44 px и
  моноширинные 14 / 16 px (терминал, Matrix, hex-дампы).
* 4-битное сглаживание (16 уровней прозрачности) — края букв не «лестницей».
* Кернинг: бинарный поиск по отсортированным парам (221 пара на начертание).
* Синтетический **bold** (двойной проход со сдвигом на ¼ px) — отдельного
  жирного файла в ядре нет, экономия ~300 КБ.
* Субпиксельное перо: позиция копится в ¼ px, поэтому строки не «плывут».
* Трекинг (разрядка) для заголовков и капса — `ui_font_draw_tracked`.
* Кодировка: CP1251 напрямую (ядро собирается с `-fexec-charset=CP1251`)
  плюс UTF-8-фолбэк, так что старые строки не ломаются.
* Метрики: `ui_font_text_width`, `ui_font_baseline_for_box` — центрирование
  считается по реальной ширине, а не по `strlen*8`.

Интеграция: `gfx_string_width_ui()` в `graphics.h/.c` — новая пропорциональная
метрика; моноширинный путь (`gfx_draw_char` и терминал) оставлен отдельно,
чтобы сетка консоли не поехала. `font8x16.{c,h}` удалены из дерева и из
`Makefile.x86_64`.

**Цена:** +~570 КБ данных шрифта в ядре, −27 КБ старого битмапа.
Если размер ядра критичен, самый дешёвый способ ужаться — убрать начертание
44 px (используется только в Ignite/Login) и генерировать 28 px масштабированием.

## 2. Панель задач и меню «Пуск» удалены

* Удалены `startmenu.c` (4 407 Б) и `startmenu.h` (1 253 Б), убраны из сборки.
* `gui.c` больше не рисует панель задач; `desktop.h/.c` — без `TASKBAR_H`.
* `wm.h/.c`, `kernel64_main.c`, `ui_theme.h` очищены от вызовов меню.

  `1-9 navigate / Enter opens / Core holds every prism`.
* Все бывшие пункты меню «Пуск» (Clock, Matrix, Tasks, Reboot, Shutdown)
  теперь регистрируются в общем реестре — они не потерялись, а переехали в Core.

## 3. Core — единственный лаунчер, построенный из реестра

`kernel/arch/x86_64/app_core.c` переписан полностью.

* Сетка 3×3 с пагинацией: 24 записи реестра → 3 страницы.
  Плитки читаются из `desktop_icon_count()` / `desktop_icon_at()`, то есть
  **список приложений теперь ровно один на всю систему** — добавили иконку в
  `kernel64_main.c`, и она сразу появилась и на рейле, и в Core.
* Таблица метаданных `META[24]`: человеческий заголовок, подзаголовок и Pearl-иконка
  для каждой записи (`«3D куб»` → `GL Cube` и т. д.).
* Появление плиток — каскад: 200 мс ease-out cubic, шаг 25 мс, сдвиг 16 px + fade.
* Правая колонка живых метрик: CORE LOAD (`cpu_stats`), MEMORY (`pmm_get_stats`),
  STRATA (`vfs_count`), аптайм (`timer_get_uptime_ms`), число активных призм и приложений.
* Клавиатура: стрелки, Tab / Shift+Tab, `[` `]` — страницы, `1`–`9` — прямой выбор,
  Enter/Space — запуск, Esc — закрыть.
* Мышь: hit-тест по карточкам с отбрасыванием зазоров (промах в 20-px щель
  между плитками не запускает соседа).
* Reboot и Shutdown — в два шага: первое нажатие переводит плитку в
  «tap again to confirm», второе выполняет.
* Повторный вызов Core не плодит окна — фокусируется уже открытое.

Вход в Core: кнопка внизу левого рейла (логические `14,906,36,36`),
слот 7 рейла, `desktop_launch_named("Core")` из любого места.

## 4. Движение

* Плитки Core — каскадное появление (см. выше).
* Подсветка левого рейла больше не телепортируется между слотами, а **едет**
  200 мс ease-out cubic (`ui_components.c`), активный слот остаётся на месте.
* `ui_components_motion_active()` добавлен в условие `interactive` в `wm.c`,
  иначе переезд рисовался бы на idle-капе 10 FPS и выглядел рвано.
* Reduced motion уважается везде: `ui_transition_progress()` при включённом
  флаге сразу отдаёт 255, а компоцитор (`compositor.c`) и так проверяет флаг
  в `compositor_anim_open/close` — специальных веток в новом коде не потребовалось.

Остаток по движению (не сделано, честно): черновой каскад появления карточек
самого рабочего стола и 530-мс мигание текстового курсора в Notes/Term.
Причина — в `desktop.c` координаты карточек зашиты абсолютно в четырёх
функциях-рисовалках; аккуратный сдвиг требует параметризации всех Y,
а это правка ~60 координат, которую без визуальной проверки в QEMU делать рискованно.

## 5. Утечка памяти при закрытии окон — исправлена

Это была настоящая, а не косметическая проблема.

`window_destroy()` существовал в `window.c` с самого начала и **не вызывался
нигде ни разу** (`grep -rn 'window_destroy' *.c` давал только определение).
Закрытие окна выставляло `close_requested = true; visible = false` — и всё.
В куче навсегда оставались:

* сама структура `window_t`;
* ARGB-буфер содержимого: `width*height*4` байт — для workspace-окна на
  1536×952 это **≈5,8 МБ за одно открытие**;
* `kmalloc`-состояние приложения (`user_data`).

То есть десяток циклов «открыл Files — закрыл Files» съедал десятки мегабайт,
а несколько десятков — всю доступную память.

Что сделано:

| Файл | Изменение |
|---|---|
| `window.h` | поля `owns_user_data` и `on_destroy(window_t*)` — явная семантика владения |
| `window.c` | `window_destroy()` теперь: `on_destroy` → `kfree(user_data)` (если владеет) → `kfree(buffer)` → `kfree(w)` |
| `wm.c` | `reap_closed_windows()` — вызывается в главном цикле после `render_frame()`; уничтожает окно только когда `close_requested` **и** анимация закрытия доиграла |
| `compositor.c/.h` | `compositor_forget_window()` — чистит слот анимации, иначе новое окно, попавшее по тому же адресу в куче, унаследовало бы чужую анимацию |
| `constellation.c/.h` | `constellation_forget_window()` — убирает окно из списка переключателя и подтягивает выделение |
| `apps.c`, `app_box.c`, `app_glcube.c`, `app_stage_e.c` | 12 мест, где состояние приложения выделяется через `kmalloc`, помечены `owns_user_data = true` |

Перед уничтожением окно вычищается из перетаскивания (`g_drag_win`), списка WM,
слота анимации и переключателя — висячих указателей не остаётся.
В serial-лог пишется `[wm] window destroyed (memory released)` — по нему удобно
проверить фикс вживую.

Проверено, что ни одно приложение не держит указатель на своё состояние в
статической глобали (`grep '^static [a-z_]*_state_t g_'` — пусто), поэтому
освобождение безопасно.

## 6. Побочно найдено и починено

**`DESKTOP_MAX_ICONS` = 16 при 19 регистрациях.** Регистрация молча
обрывалась: `Facet`, `Mesh` и `Capacity` не попадали в реестр вообще, а слот 3
левого рейла (`Facet`) был мёртвым — клик не делал ничего.
Поднято до 32, реестр расширен до 24 записей, в статический прогон добавлена
проверка «вместимость ≥ числа регистраций», чтобы это не повторилось.

Почищены устаревшие упоминания панели задач и меню «Пуск» в комментариях
`compositor.c` и в тестах `scripts/test_c5_apps.py`, `scripts/test_wm_screenshot.py`
(теперь кликают по кнопке Core), а проверка Core в `scripts/test_stage_e_static.sh`
переведена на новый реестровый контракт.

## 7. Как проверялось

* **Покомпонентная компиляция всего дерева:** 121 исходник из `Makefile.x86_64`,
  флаги сборки ядра **плюс** `-Wall -Wextra -Werror`. Результат: 117 ок, 4 падения —
  все в файлах, которых этап F не касался, и только из-за добавленного `-Werror`
  (в проекте его нет): `fat32.c:62` и `amply.c:70` — неиспользуемые статические
  функции; `gles.c:354-355` и `app_glcube.c:132-133` — `misleading-indentation`.
  Это не регрессии этапа F; чинить их — отдельная гигиеническая задача.
* **Новый статический прогон `scripts/test_stage_f_static.sh` — 30 PASS**
  (инварианты типографики, отсутствие taskbar/«Пуск», реестровый Core,
  движение, полный teardown окон, компиляция 17 затронутых модулей).
* **Регрессия: `scripts/test_stage_e_static.sh` — 32 PASS.**
* `make ARCH=x86_64` в песочнице доходит до первой же ассемблерной цели и падает
  на `nasm: No such file or directory` — ожидаемо, это ограничение среды, а не кода.

## 8. Что нужно сделать локально

```bash
make ARCH=x86_64                     # нужен nasm + grub-mkrescue + xorriso
qemu-system-x86_64 -cdrom build/myos-x86_64.iso -m 512 \
  -device VGA,xres=1600,yres=1000 -serial stdio
# скриншот через QEMU monitor: screendump /tmp/actual.ppm
python3 tools/visual_compare.py ui_reference/AmplifyOS_11_core.png /tmp/actual.png core
```

Чек-лист визуальной приёмки:

1. Ignite / Login / рабочий стол — текст пропорциональный, без «лесенки».
2. Core: 3 страницы, каскад появления, живые метрики, два шага на Reboot/Shutdown.
3. Рейл: подсветка переезжает плавно, слот Facet (3) реально открывает Facet.
4. Открыть/закрыть Files 30 раз подряд — свободная память в Capacity должна
   возвращаться к исходной, в serial-логе 30 строк `window destroyed`.
5. Проверить раскладки 1920×1080 и 1280×800 на переполнение строк
   (после перехода на пропорциональный шрифт ширины изменились везде).
